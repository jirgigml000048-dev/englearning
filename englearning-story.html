起源

他 9 岁，四年级，北京版英语课本。重度玩家—— Minecraft、宝可梦、三角洲行动。 每天打游戏几小时不在话下，但一翻开英语课本就抗拒。 最差的是阅读理解：单词认识，句子读不通，越读越烦。

家长 Gigi 一开始的诊断是：缺自信，没养成习惯。 跟我聊了几轮，我们换了一个说法——

不是学不动，是英语学习的反馈密度比游戏低两个数量级。 所以"无聊"被身体翻译成了"抗拒"。

这一句决定了产品的所有设计。每 5–10 秒必有正向反馈、永远不显示"错"、 跟读门槛一调再调到能让 80% 用户一次过、错题本悄悄塞进"今日热身"—— 所有这些都是在试图缩短这个反馈延迟。

家长的兴趣 IP 清单

  • Minecraft — 像素方块、史莱姆、苦力怕、铁傀儡、红石
  • 宝可梦 — 皮卡丘、训练师、道馆、十万伏特、对战
  • 三角洲行动 — 小队任务、侦察、手电筒、暗夜（这条要小心：9 岁 + 学习 App 不能放枪和血）

关键决策

4 天里有 7 个值得记下来的决策。每一个都是某句话触发的。

1. Vanilla HTML 还是 React？

第一天上来我做了纯 HTML/CSS/JS 的 V1，4 个关卡 + localStorage 持久化， 40 分钟跑通。然后用户给我一份"游戏元宇宙"风格的 wordmon brief：

有点太简单了 你看看这个呢...

brief 描述得诱人——捕捉、进化、合成台、宝可梦图鉴。 我兴奋地切到 React + Vite + TypeScript + Zustand， 4 小时写了一个 R1 捕捉关。然后用户回头说：

想要的是这个版本：efa4cd6（前一天的 V1 蓝紫主题）

git read-tree -u --reset efa4cd6 把工作树拉回去， wordmon 的代码留在 git 历史里，没强推。 4 小时浪费，但学到了一件事：用户描述方向 ≠ 同意架构变更。 新方向必须先 ExitPlanMode 让用户审视一份 plan，再动手。

2. 视觉风格

回到 V1 之后，用户给了一个奇怪的 URL： api.anthropic.com/v1/design/h/oBgu...。 WebFetch 返回 binary，看起来不是网页。 curl + gunzip + tar 解压出来是一份完整的 React + CSS 项目—— Minecraft 像素方块世界主题， class 命名跟我的 V1 完美对齐（明显是基于这个仓库做的设计）。

直接复用 styles.css，只重写 index.html 顶层结构 + 各模块 DOM 模板。 30 分钟从蓝紫主题切到 Voxel 主题。

3. 主题真的够"主题"吗？

我写完 12 篇阅读后用户问了一句：

这些故事和他的爱好相关吗？他的爱好是 minecraft、宝可梦、三角洲行动

我审视了一下自己的 12 篇阅读：22/24 是教材通用场景 （国庆节去动物园、京剧四大行当、找图书馆），只有"村庄"和 Steve/Alex 名字蹭了 Minecraft。 没有 Pokemon。没有任何 Delta Force。

我可以狡辩说"Steve 是 Minecraft 主角啊"，但那是骗人。 诚实回答能让协作继续下去，狡辩会失去所有信任。 我列出了真实比例，给了三个改造方案。用户选了：

我选择每个 unit 2 篇强主题，2 篇教材风。因为他真的很需要兴趣驱动。

多写了 12 篇强主题阅读：6 篇宝可梦（皮卡丘对战、宝可梦中心节日、训练师爱好）， 5 篇深度 Minecraft（钻石矿洞俱乐部、跑酷比赛、铁傀儡守卫）， 1 篇 Delta（侦察队任务，无武器无血腥）。

4. 跟读门槛

第一版录音识别用 Web SpeechRecognition， 单词重合率 50% 通过 + 3 次重试。家长跑了一次后说：

跟读门槛先低一点

改 30% / 2 次。9 岁中国孩子英语发音本身不准，加上识别引擎对儿童口音不友好—— 50% 让孩子在第三段就放弃整关。30% 让"开口尝试"就过。 目的是让他读，不是让他读对。

5. TTS 路线

用户反馈："声音还是不是很好。" iPad Safari 的 Web Speech 在国内被中文引擎接管， "apple" 听成"阿婆"。我先试着优化 voice 选择（强制选 Apple Samantha 之类高质量音色）， 用户：

还是不是很好，可以换 elevenlabs 的 key 生成吗

ElevenLabs 有 3 种集成方式：

  1. 实时 API 调用——API key 暴露在浏览器，不安全
  2. 预生成 mp3——免费层 10000 字符够一轮，零延迟，安全
  3. 自建 proxy server——用户要维护后端，重

选 2。写了一个 Node 脚本读 data.js 批量调 ElevenLabs，生成 275 个 mp3。

6. "好麻烦"

让用户本地装 Node 跑脚本，用户：

好麻烦 还有什么你可以帮我操作的方式吗

问题是我自己也帮不上——Claude Code on Web 的 sandbox 防火墙拦了 api.elevenlabs.io（"Host not in allowlist"）。 我做不了直接帮跑。但我们之间还有一个共同能到达的地方： GitHub Actions。

写了一个 workflow，workflow_dispatch 触发， 用户在 GitHub 网页点 Run workflow → CI 跑 ElevenLabs 脚本 → 自动 commit mp3 → push。 用户唯一要做的是去 Settings 加一次 ELEVENLABS_API_KEY secret， 之后所有事在 GitHub 网页上完成。

7. Android APK 还是 PWA？

最后一个问题，触发了整个项目最大的架构调整：

netlify 需要 vpn 才能打开 ... 最好做成 android 版的 app，他的 pad 是 oppo pad4

在国内用户家里访问 Netlify 偶尔被墙。PWA 也不行——还得先打开网页才能 install。 要彻底解决：Capacitor 把整个网页打包进 APK， 包括所有 mp3。装到 Pad 后零网络依赖。

又是一个 GitHub Actions workflow：用户点 Run， CI 跑 npm install + cap sync + gradle assembleDebug， 约 10 分钟出一个 35 MB 的 APK，自动发到 Releases 页。 用户从 GitHub Releases 下载到 Pad，安装即用。

  • ⚔ 拼写打怪——5 只像素史莱姆/苦力怕，前 2 只优先错题词。

"看不到的算法"

错题本：每个词记 correctStreakSinceWrong。 错一次重置为 0，答对 +1。≥ 3 时退出错题本（"掌握"）。 Anki 默认 4 次，多邻国 3 次，我也用 3。

Unit 自动进阶：当前 Unit ≥ 80% 词不在错题本 + 至少完成 1 篇阅读 → 弹 toast "🎉 Unit 1 已掌握！进入 Unit 2" → 自动跳。 家长不用手动切，孩子按自己节奏推进。

每日轮换：state.dailyLessonPlan 当天选 6 个词后存死， 同一天反复进新词关复用同一份。第二天换新一批。

10 个真实踩坑

① 沙箱出口防火墙

症状调外部 API 全 403 "Host not in allowlist"

影响Netlify deploy / Cloudflare tunnel / ElevenLabs / Quark 网盘

修复所有 user-side 工作挪到 GitHub Actions（受限用户的"远程 shell"）

② Service Worker 缓存住老版本

症状用户清缓存前看不到新代码效果

根因cache name etrainer-v1 没变 + cache-first 策略

修复bump 名字到 etrainer-voxel-v3 + 改 network-first

③ Wordmon 过度设计

症状用户回头要 "efa4cd6 那个版本"

根因把"游戏元宇宙"想得太重，浪费 4 小时

修复git read-tree --reset 回退，保留历史不强推

④ 主题感虚假

症状24 篇阅读只有 Steve/Alex 蹭 Minecraft，没 Pokemon 没 Delta

根因优先教材考点 → 主题被牺牲

修复2 教材 + 2 强主题比例，每篇先列"必含 IP 元素"再写

⑤ TTS Voice Picker bug

症状设置里下拉选不动，选了没效果

根因两处用 onvoiceschanged = ... 互相覆盖

修复改成 addEventListener（多 listener 共存）+ 实时查询不依赖缓存

⑥ 跟读门槛太严

症状孩子读完 30% 还过不去 → 挫败 → 拒绝阅读关

根因50% / 3 次 是成年人发音的基线

修复30% / 2 次。"开口尝试就过"

⑦ Netlify 在国内访问慢

症状"netlify 需要 vpn 才能打开"

根因Netlify edge servers 不在国内

修复Capacitor 打 Android APK，所有资源内嵌，零网络依赖

⑧ 朗读全文在 WebView 没声音

症状单词/跟读有 ElevenLabs 声音，"朗读全文"哑火

根因朗读全文走 Web Speech，Android WebView 的 speechSynthesis 常缺音色

修复改成顺序播放每段 mp3，首段失败才回落 Web Speech

⑨ APK 构建 exit code 127

症状Build APK workflow 跑 22 秒就挂，exit 127 (command not found)

根因cap add 生成的 gradlew 丢了 +x 权限，而 || echo 吞了真错误

修复set -e + chmod +x gradlew + 每步 test -f 显式校验

⑩ 侧载 APK 给不了麦克风权限

症状ColorOS 设置 → 应用 → 权限里根本没"麦克风"这项

根因Capacitor 默认 manifest 没声明 RECORD_AUDIO

修复构建时往 manifest 注入 RECORD_AUDIO，系统才会弹权限请求

协作方法

用户输入特征

  • 直接简短。用 Markdown 列要求："1、2、3 都想做"。
  • 质疑前先问。"这些故事真的和他爱好相关吗？"
  • 不满意敢回退。"想要的是这个版本：efa4cd6"
  • 真实使用反馈。"跟读门槛先低一点。""声音还是不是很好。"

AI 输出特征

  • GitHub UI 步骤化。所有用户操作翻译成"打开 X 页面 → 点 Y 按钮"。
  • 每次提交后给 3 段说明。「这次改了什么」「您要做什么」「下一个想做哪个」。
  • 主动审计自己。"诚实回答：只有微弱关联。"
  • 提议时排优先级 + 给工作量。所有 backlog 按"分数提升杠杆 + 工时"排队。
  • plan 模式先于代码。复杂改动用 ExitPlanMode 让用户先审 plan。

反馈循环

每个循环 ≤ 30 分钟：

  1. 用户在 Pad 上让孩子玩 10–30 分钟
  2. 孩子卡在某个点 / 抗拒某个交互
  3. 用户告诉 AI 「跟读门槛太严」
  4. AI 1 个 commit + push + 3 行解释
  5. 用户清缓存看 / 让孩子再试
  6. 反馈下一个痛点 → 回 1

教训

关于产品（给孩子用的学习 App）

  1. 反馈密度 = 留存。儿童学习 App 跟游戏抢的不是知识，是注意力时间。每 5–10 秒必有正反馈是底线。
  2. 绝不显示"错"。所有失败要包装成"再试一次"。9 岁孩子在红叉面前的条件反射就是关闭 App。
  3. 兴趣驱动 > 教学严谨。偏离教材一点没关系，让孩子愿意打开下一次更重要。完美教材覆盖但孩子不开 = 0 学习。
  4. 掌握判定要松。50% 阈值劝退；30% 阈值还能让孩子读出第二段。让"开口尝试"就过。
  5. 每天有变化 > 完整覆盖。同一 Unit 反复做但内容变 = "我每天都在前进"。
  6. 错题本 + 间隔重复 = 隐形进度。孩子不主动复习，但你可以用"今日热身"自动塞他错过的题。

关于 Vibe Coding 协作

  1. 微提交是金矿。22 commits 让回退、审计、解释、auto-deploy 都简单。
  2. 诚实审计自己的工作。用户问"X 是 Y 吗"立刻承认局限。撒一次谎失去全部信任。
  3. 小心"过度设计"诱惑。React + 状态机 + 类型系统的方案听着对，但用户实际只需要 4 关 + localStorage。
  4. 写 plan 先于写代码。ExitPlanMode 强制慢一拍，避免 wordmon 那 4 小时。
  5. 把外部依赖当成可能失败的。Netlify / ElevenLabs / Cloudflare 都可能不可达。
  6. 用户每说"好麻烦"，反思自动化。GitHub Actions 是受限用户的"远程 shell"。

关于技术选择

  1. Vanilla > Framework，前提是单页 + 内容驱动 + 跨设备 + 没团队。
  2. localStorage > 后端，前提是单用户 + 不需要同步 + 隐私敏感。
  3. 预生成 mp3 > 实时 TTS API，前提是内容固定 + 零延迟需求 + key 不能进浏览器。
  4. Capacitor > React Native / Flutter，前提是已有网页 + 要快速打包 + 不需要原生 UI。
  5. "国内 + 离线" → APK 默认。评估用户网络环境是产品决策，不是部署决策。
  6. 移动端打包是"第二个项目"。WebView ≠ 浏览器：Web Speech 可能缺、权限要在 manifest 先声明、CI 要 chmod gradlew。浏览器测得再好，真机会暴露全新一批问题。
